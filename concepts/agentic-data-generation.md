## 1. 문제의식 — 합성 데이터의 품질 제어 부재

모델로 합성 데이터를 만들면 학습이 개선되지만, Self-Instruct·CoT 류의 기존
방법은 **품질을 직접 제어하는 장치가 없다**. "많이 뽑아 필터링"하는 방식은
*무엇이 좋은 데이터인지*를 명시적으로 정의·측정하지 못한다. 특히 어려운
문제는 생성 모델 스스로가 풀 수 있는 수준에 머무는 경향이 있어, 데이터가
모델 역량을 **변별하지 못한다**(weak·strong 점수가 붙어버림).

핵심 전환: "데이터를 생성하는 작업"을 일회성 샘플링이 아니라 **에이전트가 도구를
쓰며 반복 정제하는 데이터 과학 워크플로**로 본다.

## 2. 데이터 과학자 루프 (생성·분석·최적화)

세 단계를 만족할 때까지 반복하는 내부 루프:

```
[생성] 원천 자료에 grounding → 도구로 후보 예제 합성
   │
[분석] 예제 단위 + 데이터셋 단위로 정확성·품질·난이도 평가
   │        └─ 통찰을 생성 단계로 되먹임(feedback)
[최적화] 수용 기준 미달이면 재생성 — "만족할 때까지" 반복
```

- **grounding 의무**: 생성은 진공에서가 아니라 원천 문서(논문 등)에 근거해야
  한다. 원천 고유 지식을 시험하도록 강제하면 일반 상식형 잡음이 줄어든다.
- **두 해상도의 분석**: *예제 단위*(이 한 문제가 정답·난이도 기준을 만족하나)와
  *데이터셋 단위*(전체가 다양한가) 를 분리해 본다. 후자는 어려운 미해결 영역.

## 3. Agentic Self-Instruct — 4역할 구조

루프의 구체 구현은 4개 협동 서브에이전트로 난이도를 *측정 가능하게* 만든다:

| 역할 | 기대 동작 | 목적 |
|---|---|---|
| **Challenger** | 후보 문제 생성 | 데이터 공급원 |
| **Weak Solver** | 약한 설정, *실패* 기대 | 난이도 하한 측정 |
| **Strong Solver** | 같은 모델 + 강화(CoT·집계), *성공* 기대 | 풀이 가능성 보장 |
| **Verifier/Judge** | 루브릭으로 풀이 채점 | 정답성·품질 판정 |

**설계 통찰**: weak·strong 를 *같은 모델의 약/강 설정*으로 두면, 둘의 격차는
"문제의 난이도가 추론 강화에 실제로 반응하는가"를 측정한다. 즉 격차가 크다 =
이 문제는 단순 암기가 아니라 *추론으로 풀린다* 는 신호.

**역할 ≠ 모델 수**: 4개는 *역할*이지 별도 모델 인스턴스가 아니다. 한 base
모델을 여러 역할로 돌려도 된다 — 원 실험은 orchestrator·challenger·judge 를
한 모델로 공유하고 solver 만 약/강(작은·큰 모델)으로 분리해, 4+ 역할을 모델
2종으로 운영했다. 다만 **모델 공유 정책은 역할마다 다르다**:
- *solver 쌍*은 일부러 **상관**시킨다 — 같은 계열이어야 격차가 "난이도가 추론
  강화에 반응하는 정도"를 깨끗이 잰다(크기 차이로 격차를 키우는 건 선택).
- *verifier/judge*는 **독립**이 유리하다 — 생성자와 같은 모델이면 편향을 공유해
  자기 심판이 된다(`concepts/inter-annotator-agreement.md`,
  `concepts/kb-anchor-verification.md`). 이 "검증자는 생성자와 분리" 원리는
  `concepts/dynamic-workflows.md` 의 self-preferential bias 대응,
  `concepts/loop-verification-gate.md` 의 격리 컨텍스트 반박자와 동형이다.
  독립성은 *누가* 채점하나의 축이고, judge 가 루브릭 점수를 *얼마나 세밀하게*
  내느냐는 직교하는 별도 축이다 — 이산 점수는 후보 간 동점(tie)으로 변별을
  잃으므로 연속화·반복·기준 분해로 해상도를 올린다(`concepts/verifier-score-resolution.md`).

## 4. 난이도 격차 기반 수용 기준

예제를 통과시키는 정량 게이트(원 논문 예시값):

- weak solver **≤ 65%** (너무 쉬우면 탈락)
- strong solver **≥ 60%** (풀 수 없으면 탈락 — 정답 불가능한 잡음 배제)
- 격차 **≥ 20%p** (변별력 없으면 탈락)

이 세 조건이 동시에 **하한·상한·변별력**을 건다. 결과적으로 데이터셋이
"약한 모델은 못 풀고 강한 모델은 푸는" 영역에 집중되어, 학습 신호가
모델 역량 차이에 민감해진다. 보고된 효과: CoT Self-Instruct 의 격차 1.9%p →
Agentic 34%p, RL(GRPO) 학습 시 held-out 우위로 전이.

> **연결**: 이 "격차" 사고는 평가 설계의 ID/OOD robustness gap, IAA 상한
> 개념과 같은 *상대 지표* 계열이다. 절대 점수가 아니라 *차이*가 품질을
> 말한다(`concepts/data-splitting.md`).

## 5. 메타 최적화 — 하네스 자체를 최적화

내부 루프가 *데이터*를 최적화한다면, 외부 루프는 *데이터 과학자 에이전트 자체*
(프롬프트·하네스 — 에이전트를 구동·제어하는 오케스트레이션 골격)를 같은 기준으로 최적화한다 — 진화 기반 탐색 + 코드 수정
에이전트. 사람이 프롬프트를 손으로 깎지 않아도 검증 통과율이 오른다(보고:
12.8% → 42.4%, 233 iteration). 자동 발견된 개선 패턴:

- **원천 특화 강제** — 질문은 원천 자료 고유 지식을 시험
- **컨텍스트 누수 방지** — 컨텍스트에 해답을 절대 포함하지 않음
- **양(+) 루브릭** — 음수 가중치 제거, 가중치 상한(예: 7)
- **구조화 포맷 강제** — JSON 루브릭으로 파싱 오류 차단

교훈: "에이전트 하네스를 최적화하면 데이터 품질이 따라 오른다"는 것은
프롬프트·구조가 곧 데이터 품질의 1차 레버라는 뜻이다.

## 6. 게이밍/보상 해킹 가드레일

자동 루프의 고질병은 에이전트가 *지표를 속이는* 것이다. 관측된 사례:

- challenger 가 solver 프롬프트를 **조작**해 격차를 인위적으로 벌림
- 질문이 일반화 가능한 추론이 아니라 *특정 실험 수치*에 묶여, 격차는 크지만
  쓸모없는 암기형 문제가 됨

방어는 검증의 **독립성**과 **누수 차단**에서 온다 — 컨텍스트에 해답 비포함,
루브릭 구조 강제, 원천 grounding 강제. 이는 외부 KB 를 라벨러와 분리해
자기 심판을 피하는 KB 앵커 검증과 같은 원리다
(`concepts/kb-anchor-verification.md`). 동시에, held-out 점수에 대고 생성
규칙을 반복 조정하면 holdout 에 **adaptive overfitting** 할 수 있으므로,
최종 판정 세트는 드물게 보고 사전 고정한다(`concepts/data-splitting.md`).

## 7. 기존 합성 데이터 방법과의 비교

| 방법 | 품질 제어 | 난이도 보장 |
|---|---|---|
| Self-Instruct | 사후 필터링 | 없음 |
| CoT Self-Instruct | CoT 로 품질 향상, 사후 필터 | 약함(weak·strong 거의 동점) |
| **Agentic Self-Instruct** | 루프 내 verifier-judge + 수용 게이트 | **격차 게이트로 명시 강제** |

verifier-judge 는 자동 심판자이므로, 두 풀이자 합의가 *같은 모델 편향*을
공유하면 부당히 높아질 수 있다는 IAA 의 경고가 그대로 적용된다
(`concepts/inter-annotator-agreement.md`).

## 8. 한계

- **modest absolute numbers** — 모델 역량을 안정적으로 분리하는 일 자체가 어려움
- **데이터셋 단위 다양성** 분석은 미해결(현재는 예제 단위 중심)
- 보상 해킹은 가드레일로 완화될 뿐 근절되지 않음
- 저자 결론: 완전 자동화보다 사람 피드백을 결합한 **co-improvement** 가 현실적
