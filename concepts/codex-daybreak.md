# Codex의 Daybreak 모델 선택과 접근 모드

> 모델 선택, Daybreak 접근 등급, 요청별 활성화는 구분해야 하며, 거절 완화가 보안 성능의 우위를 보장하지는 않는다.

## 개요

이 문서는 Codex CLI에 ChatGPT 계정으로 로그인하여 Daybreak를 사용하는 경우를 중심으로 정리한 문서다. 확인 기준일은 2026-10-28이다. API 호출 방법과 API 모델 별칭의 폐기 일정은 다루지 않는다. 계정 권한, 모델 목록, CLI 버전과 관리자 설정에 따라 제공되는 기능이 달라질 수 있다.

Daybreak Blue와 Red는 Trusted Access for Cyber의 접근 등급이다. Blue는 지원되는
일반 모델에서 승인된 방어 보안 작업의 불필요한 거절을 줄이는 접근을 제공한다.
Red는 별도 승인 아래 고급 보안 작업과 전문 사이버 모델 접근을 제공한다.
Blue 접근 등급과 모델 선택기에 표시되는 **Daybreak Blue 항목**은 구분한다.

근거: `sources/dev/openai-daybreak-overview.md`.

## 핵심 원칙

1. **모델과 접근 모드를 구분한다.** 모델 ID를 선택하는 것과 이후 요청에
   Daybreak 처리를 적용하는 것은 서로 다른 설정이다.
2. **기능 표시, 접근 승인, 실제 적용을 구분한다.** 명령이 표시되거나 토글이
   켜졌다는 사실만으로 선택한 모델에 거절 완화가 적용됐다고 판단하지 않는다.
3. **거절 완화와 문제 해결 능력을 구분한다.** 요청을 더 자주 수행한다는 것과
   취약점을 더 정확히 발견하거나 안전한 패치를 만든다는 것은 별도로 검증한다.
4. **비교 결과의 조건을 보존한다.** 모델, 하네스, 작업 집합, 추론 수준과
   승인 조건이 다른 자료를 동일한 비교 결과로 합치지 않는다.
5. **근거 없는 사용 순서를 권장하지 않는다.** 일반 모델부터 시작해 Blue,
   Red로 전환하는 순서가 최선이라는 직접 검증은 확보하지 못했다.

## 세부 설명

### 모델 선택과 Daybreak 활성화

| 설정 | 역할 |
| --- | --- |
| `/model` | 대화에서 사용할 모델을 선택한다. |
| `/daybreak` | 이후 요청에 적용할 Daybreak 설정을 켜거나 끈다. |
| `features.cli_daybreak` | CLI의 Daybreak 조작 기능을 활성화하거나 숨긴다. 접근 승인을 부여하지는 않는다. |

모델 선택기의 Daybreak Blue 항목은 `gpt-daybreak-blue-latest`라는 ID로 식별된다.
GPT-6 Sol을 선택한 뒤 Daybreak를 켜는 경우에는 선택한 모델 ID가 다르다.
이 차이만으로 두 항목의 실제 서버 가중치나 보안 능력 차이를 확정할 수는 없다.
특히 API 문서의 별칭 연결을 Codex의 실제 기반 모델을 확인한 증거로 대체하지 않는다.

공식 CLI 안내에 따르면 `/daybreak`의 선택은 활성 대화에 적용되며 새 세션의
기본값으로도 저장된다. 재개하거나 분기한 대화는 저장된 Daybreak 선택을 유지하므로,
설정 파일의 새 기본값이 기존 대화까지 바꾼다고 가정하지 않는다.

근거: `sources/dev/openai-daybreak-cli.md`.

### 모델별 승인 조건

다음 표는 공식 문서의 거절 완화 조건이다. 해당 모델과 제품에 대한 접근 권한도
충족해야 하며, 승인과 별도로 Daybreak를 요청에 활성화해야 한다.

| 모델 | Blue 승인과 Daybreak 활성화 | Red 승인과 Daybreak 활성화 |
| --- | --- | --- |
| GPT-6 Sol | 거절이 완화된다. | 거절이 완화된다. |
| GPT-6.1 Sol | 일반 안전장치가 유지된다. | 거절이 완화된다. |
| Astra | 일반 안전장치가 유지된다. | 거절이 완화된다. |

따라서 GPT-6.1 Sol에서 Daybreak를 켰다는 표시만으로 Blue 승인의 거절 완화가
적용됐다고 설명해서는 안 된다. Blue와 Red를 모든 모델에 공통으로 적용되는
성능 단계로 해석해서도 안 된다.

일반 안전장치 아래에서도 보안 코드 검토, 위협 모델링과 패치 작업을 수행할 수
있다. 공식 문서는 Blue를 대부분의 보안 팀이 검토할 시작점으로 권장하지만,
이는 특정 일반 모델보다 먼저 또는 나중에 사용해야 한다는 성능 비교 결과가 아니다.

근거: `sources/dev/openai-daybreak-overview.md`.

### CLI에서 명령이 보이지 않을 때

설치 버전과 유효한 기능 설정을 먼저 확인한다.

```bash
codex --version
codex features list
```

`cli_daybreak`가 꺼진 환경에서는 다음과 같이 새 CLI를 시작해 명령 표시를
확인할 수 있다. `--no-daemon`은 기존 백그라운드 서버와 분리해 시작하기 위한
옵션이며, Daybreak를 사용하는 모든 환경의 필수 옵션은 아니다.

```bash
codex --no-daemon --enable cli_daybreak
```

이 방식은 CLI 0.165.0에서 명령 표시와 켜짐·꺼짐 전환까지 관측됐다.
실제 모델 요청의 접근 처리나 거절률을 검증한 결과는 아니다. 기능 플래그를
켜는 것과 계정에 Daybreak 권한이 부여되는 것은 구분한다.

근거: `sources/dev/openai-daybreak-cli.md`의 버전·기능 설정 및 검증 범위.

### 성능 비교 자료의 해석

2026년 8월 공개된 개인 벤치마크는 Hermes 하네스에서 소프트웨어 작업 40개를
평가하여 Daybreak Blue가 37개, 일반 GPT-5.6 Sol이 32개를 해결했다고 보고했다.
보고서는 두 조건을 같은 GPT-5.6 Sol 기반 스냅샷으로 선언된 서로 다른
접근·정책 조건으로 설명한다. 대응 비교의 McNemar 검정값은 `p = 0.0625`였다.

이 결과는 해당 작업 집합에서 관측된 차이다. Codex CLI 자체의 직접 비교도,
GPT-6.1 Sol과의 비교도 아니다. 보고서는 다른 가중치나 일반적인 능력 격차를
입증하지 않는다고 명시한다. 이번 정리는 실험 재현이나 공개 산출물의 무결성
검증을 수행하지 않았다.

근거: `sources/dev/bryann2k-llm-engineering-benchmark.md`.

보안 연구자의 사용 기록에는 취약점 발견에 도움이 됐다는 경험과, 반복적인 범위
확인과 중단으로 작업성이 나빠졌다는 경험이 함께 나온다. 작성자는 비교에 사용한
자식 세션이 부모의 지침을 상속하여 깨끗한 모델 비교가 아니었다고 정정한다.
이런 후기는 작업상의 문제를 찾는 자료로 사용하고 성능 순위의 근거로 일반화하지 않는다.

근거: `sources/dev/qian-daybreak-instruction-change.md`.

### 확인되지 않은 사항과 제외하는 결론

- Codex의 Daybreak Blue와 실제 거절 완화가 적용된 GPT-6.1 Sol을 동일 조건에서
  비교한 성능 근거는 이번 조사에서 확보하지 못했다.
- Codex의 Daybreak Blue가 어떤 서버 스냅샷으로 처리되는지는 이번 조사에서
  직접 식별하지 못했다. 모델 표시명만으로 독립된 학습 모델이라고 단정하지 않는다.
- Daybreak Blue가 취약점을 더 잘 찾거나 패치를 더 안전하게 만든다는 보편적
  우위와, 특정 모델을 먼저 사용해야 한다는 최적 순서는 확인하지 못했다.
- 공개 패치 공지를 찾지 못했다는 관측은 모델 패치가 없었다는 증명이 아니다.
  문서의 갱신 시각을 모델 갱신 시각으로 해석하지 않는다.
