# 컨텍스트 엔지니어링 (Context Engineering)

> LLM이 글을 읽는 원리(관련도 기반 어텐션·lost-in-the-middle·유한 윈도우)에서 출발해, 모델이 볼 전체 토큰을 *무엇으로·얼마나·어떤 순서로* 채울지 설계하는 일. 한 줄을 다듬는 프롬프트 엔지니어링을 대체한다.

## 개요

컨텍스트 엔지니어링은 "모델에게 잘 부탁하는 법"이 아니라 **"모델이 어떻게 읽는지 알고 무엇을 컨텍스트로 줄지 설계하는 일"**이다. 초점이 프롬프트의 한 줄(프롬프트 엔지니어링)에서, 모델이 한 번에 보는 전체 토큰 — 시스템 프롬프트·대화 이력·도구 결과·생성 중인 답 — 을 어떻게 구성할지로 이동한다.

## 핵심 원칙 — LLM이 글을 읽는 세 가지 기제

1. **어텐션은 순서가 아니라 관련도로 읽는다.** 모든 단어 쌍의 관련도를 계산하므로 입력이 길수록 계산량이 제곱으로 늘고 주의가 묽어진다. 무관한 정보는 중립 노이즈가 아니라 **능동적으로 해롭다** — 관련된 지시와 자료를 함께 묶어야 어텐션 가중치가 높다.
2. **lost-in-the-middle.** 입력 중간의 정보는 활용도가 떨어진다. 핵심 지시는 앞·끝에 두고, 구조 표지(XML 태그·markdown 제목)로 위치를 준다. → `concepts/session-handoff.md`가 이를 "context rot"(60% 사용률 근처 품질 저하)로 다룬다.
3. **컨텍스트 윈도우는 유한한 공유 공간.** 여러 구성요소가 같은 공간을 나눠 쓰며, 누적물이 핵심 가이드를 밀어낸다. "긴 컨텍스트는 쓰레기를 더 담을 뿐 중요한 걸 더 잘 고르게 하지 않는다."

## 세부 설명

### 저술 원리 (Do / Don't)

세 기제에서 파생되는 실천 규칙:

| Don't | Do |
|---|---|
| 관련 있어 보이면 다 넣기 | 필요한 것만 큐레이션 |
| 중요도 무관하게 나열 | 핵심은 앞·끝 |
| 길수록 정확하다 믿기 | 길이는 비용·노이즈, 충분한 만큼만 |
| 절차를 떠먹이기 | 목표·성공 기준 주고 맡기기 |
| 금지 사항 나열 | 원하는 행동을 긍정형으로 |
| 로직까지 few-shot | 예시는 형식·톤 고정용 |
| 규칙을 특정 케이스로 못 박기 | 경계를 원리로 |
| 한 프롬프트에 큰 작업 몰기 | 하위 작업은 정제된 목표만 분리 |
| "이거 괜찮지?" 확인 | "약점·반례부터 찾아줘" 반증 |
| 한 번 좋았으니 늘 좋다 | 출력은 확률, 중요한 건 재확인 |
| 최신 모델이니 무조건 짧게 | 대상 모델 성격에 맞춰 |

### 가이드라인 vs 하네스

여기서 **하네스(harness)** 는 모델을 정해진 절차로 구동하고 검증까지 붙들어 두는 장치를 뜻한다.

| 구분 | 가이드라인 | 하네스 |
|---|---|---|
| 다루는 것 | 무엇을 **알아야** 하는가 (지식·맥락) | 어떻게 **행동**해야 하는가 (절차·검증·중단 조건) |
| 내용 | 규칙·정의·예시 | 출력 형식 계약·검증 루프·중단 기준 |
| 강할 때 | 모델이 도메인을 모를 때 | 입력이 들쭉날쭉해도 일관성이 필요할 때 |

**두 "하네스"의 층위 구분** — 여기서 하네스는 *프롬프트 안의 행동 규정* 층이다. `concepts/dynamic-workflows.md`의 하네스는 *다중 에이전트를 구동하는 오케스트레이션 골격* 층이다. 둘 다 "절차를 떠먹이는 대신 성공 기준을 못 박고 자율 실행·검증하게 붙든다"는 같은 원리의 다른 고도이며 상보적으로 쓴다.

### 결정 소유권의 레이어 고정

모호한 장문 규칙은 원자 단위로 분해하고, 각 결정을 특정 레이어에 고정해 모델이 매번 재해석하지 않게 한다.

### 모델 세대에 따른 조정

- **최신 추론 모델**: 절차 최소화, "무엇이 성공인지"만 제시. few-shot은 형식·톤 고정용(→ `concepts/bio-tagging.md`가 출력 형식 고정에 이 원리를 실제 적용). "단계별 사고" 강제는 오히려 성능 저하.
- **구형·경량 모델**: few-shot·단계별 가이드 유효, 검증 규칙을 더 촘촘히.
- 원리는 불변이나 그 위 권장 사용법은 모델 세대에 따라 바뀐다.

### 아첨(sycophancy)과 출력의 확률성

RLHF로 학습된 모델은 사용자에게 동의하려는 경향이 있어 확인형 질문("이거 괜찮지?")은 검증을 무디게 한다 — 반증형("약점·반례부터")으로 재구성한다. 또 출력은 확률적이라 한 번 좋은 결과가 늘 재현되지 않으므로, 중요한 산출물은 다시 확인한다.
