# Loop Verification Gate (격리 컨텍스트 반박자 게이트)

> 자동 지속 루프의 완료 시점에, 싸고 결정적인 검사를 먼저 통과시킨 뒤 격리 컨텍스트의 반박자가 산출물을 반증하게 하여 거짓 완료를 막는 검증 게이트.

## 개요

`loop until done` 류의 자동 지속 루프(에이전트가 "완료"를 선언할 때까지 반복)는 `concepts/dynamic-workflows.md` 의 세 실패 모드 — 특히 게으른 조기 완료와 자기 출력 편애 — 에 취약하다. 루프 검증 게이트는 **완료 선언 시점**에 끼어들어, 통과하지 못하면 완료를 막는다. adversarial verification 패턴을 완료 게이트로 구체화한 것이다.

## 핵심 원칙

1. **싼 것 → 비싼 것 순서 (fail fast)**: 결정적 검사(린트·테스트·체크섬처럼 코드로 참거짓이 나오는 것)를 먼저 돌리고, 통과해야 토큰 드는 적대적 검증 에이전트를 띄운다.
2. **격리 컨텍스트 반박자**: 산출물을 만든 본인이 아니라, 기억이 깨끗한 서브에이전트가 *승인이 아니라 반증*을 임무로 검사한다 (self-preferential bias 대응).
3. **판정 산출물을 확인한다**: 게이트는 모델의 "검증했다"는 자기보고가 아니라, 반박자가 남긴 *판정 산출물*을 직접 읽어 통과를 결정한다. 판정 자체에도 오류가 있을 수 있으므로 근거와 검사 범위를 함께 확인한다.
4. **비교 판단**: "좋은가?"가 아니라 "재실행 결과가 보고값과 같은가?"처럼 비교형으로 검증한다.

## 세부 설명

### 게이트 흐름

완료 선언(루프의 정지 시도) → ① 결정적 선통과(실패 시 차단) → ② 격리 반박자 판정 요구 → 판정이 통과면 완료 허용, 실패면 결함을 돌려주고 재작업.

### 안전장치 (필수)

다음은 위키의 게이트 설계 제안이다. 실제 훅의 재진입·종료 동작은 실행 환경의 문서와 대조한다.

- **발동 범위 한정**: 게이트는 자동 루프가 활성일 때만 작동시켜, 일상 단발 작업에 끼어들어 비용·간섭을 키우지 않는다.
- **재진입 상태 확인**: 직전 검사 결과와 진행 상황을 확인하여 해소 불가능한 조건을 반복 차단하지 않는다. Claude Code의 `stop_hook_active`는 Stop 훅에 의해 계속 실행 중임을 알리는 값이며, 재진입 자체가 검증 통과를 뜻하지 않는다.
- **무한루프 차단 + 에스컬레이션**: 누적 차단 횟수 상한을 두고, 초과하면 루프를 중단하되 **검증 미통과 상태**와 남은 결함을 보존하여 사람에게 넘긴다. 실행 환경이 반복 차단을 해제하여 턴을 끝내더라도 검증 통과로 기록하지 않는다.
- **킬 스위치**: 강제 비활성 경로를 두되 비활성화 사실을 검증 결과와 구분한다.

Claude Code의 Stop 훅 동작에 대한 근거는 `sources/dev/anthropic-claude-code-hooks.md`를 참고한다.

### 비용 (적대적 검증을 자동화할 때)

다음은 비용을 평가할 때 고려할 변수이며, 특정 모델이나 워크로드의 절감 효과를
검증한 결과는 아니다.

- **호출 빈도**: 매 정지 시도에 검증자를 부르는 경우와 산출물 단위로 부르는 경우의
  비용·검증 누락 가능성을 함께 비교한다.
- **대기 시간과 캐시 조건**: 검증자 실행 시간과 해당 제공자의 캐시 유효기간·과금
  조건을 확인한다. 별도 세션이라는 이유만으로 캐시 재사용이나 비용 절감을 보장하지 않는다.
- **검증자 모델**: 더 저렴한 모델을 사용하려면 대표적인 결함을 검출하는 능력과
  오탐률을 먼저 평가하고, 비용만으로 등급을 낮추지 않는다.
