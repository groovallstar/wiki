# 바이브 코딩의 토큰 관리 전략

> "토큰 부족은 모델 성능의 문제가 아니라, 대개 컨텍스트 운영 방식의 문제다."

Claude Code, Codex, Gemini 같은 도구 사용 시 응답 지연, 규칙 망각, 불필요한 파일 수정 등이 발생하는데, 이는 "토큰 부족"이 아니라 **컨텍스트 오염(Context Rot)**의 증상이다.

> **읽기 전에 둘.**
>
> **관측 시점** — 아래 도구 운용 항목(슬래시 명령·설정 파일·Skills 로딩·MCP)은 **2026-08 시점** 기준이다. 이 페이지는 원리가 아니라 특정 제품의 작동 기제를 담고 있어서, 원칙보다 수단이 먼저 낡는다. 실제로 §1 의 차단 수단은 한 번 바뀌어 정정된 적이 있다. 수단이 지금도 그대로인지 확인하고 쓴다.
>
> **절감률의 출처** — 본문의 절감 수치는 전부 §출처의 블로그 한 건에서 왔고, 워크로드·측정 방법·비교 대상이 원문에 없다. **저자가 보고한 단일 사례**로 읽는다. 어느 조치가 크게 듣는지의 *순서*는 참고할 수 있지만, *크기*는 다른 환경으로 옮길 근거가 없다.

---

## 1. 불필요한 파일을 컨텍스트에서 차단

가장 높은 ROI를 가진 단일 조치. 빌드 산출물, 모델 가중치, 로그, 미디어
파일, 볼륨, IDE 설정 등 컨텍스트에 도움이 되지 않는 파일을 자동 로딩에서
제외한다.

**핵심**: 절약이 아니라 도움 안 되는 정보를 차단하는 것.

> 검증 메모: 원문은 `.claudeignore` 파일(`.gitignore` 문법)로 차단하면
> 30~40% 절감이 가능하다고 적었으나, 현행 Claude Code에는 `.claudeignore`가
> **구현돼 있지 않다** — 요청 단계의 open issue 다수, 나열해도 파일이 그대로
> 읽힌다. 실제 작동 기제는 설정 파일(`.claude/settings.json`)의
> `permissions.deny` 규칙이다. 따라서 *원칙*(불필요 파일을 컨텍스트에서
> 차단)은 유효하되, *수단*은 `permissions.deny`로 대체해 적용한다.

## 2. `tasks.md` 분할로 인덱스 구조 도입

큰 단일 태스크 파일 대신 변경 단위별로 tasks.md를 분리하고 완료된 것은 archive로 이동한다. 추가로 고려할 점:

- 각 tasks.md에 현재 상태 요약을 상단에 두어 전체를 읽지 않아도 진행 상황을 파악할 수 있게 한다
- archive 디렉토리를 활용하여 완료된 작업을 격리한다

**저자 보고 ~76% 절감**(사례 1건). 원문은 76.1% 로 적었으나 단일 사례에서 나온 값이라 소수점 자리가 정밀도를 과장한다.

---

## 3. `/clear`, `/compact` 전략적 활용

| 명령 | 용도 |
|------|------|
| `/clear` | 작업 맥락 완전 초기화 |
| `/compact` | 중요 내용만 유지하며 대화 요약 |

**사용 타이밍:**
- 디버깅 세션 완료 후
- 하나의 기능 구현 완료 후
- 컨텍스트 사용량 70% 도달 시 — 품질 저하는 60% 근처부터 시작되므로(`concepts/session-handoff.md`), 저하가 누적되기 전 여유를 두고 정리한다

**철학**: 긴 세션 유지보다 "짧게 끊고 재시작"하는 능력이 중요하다.

> `/compact`는 focus 지시 없이는 결과가 예측 불가능하다는 경고, 그리고 auto-compact가 *가장 덜 똑똑한 순간*에 발동하는 비대칭 문제에 대한 상세는 `concepts/session-handoff.md` §Tier 1 참조.

---

## 4. Handoff 문서로 세션 재개 비용 최소화

세션 종료 전 `HANDOFF.md`를 작성하여 다음 세션에서 즉시 작업을 재개할 수 있도록 한다.

```markdown
# HANDOFF.md

목표: <현재 작업 목표>
수정한 파일: <변경된 파일 목록>
확인한 사실: <디버깅/조사 결과>
실패한 시도: <시도했으나 실패한 접근>
다음 작업: <이어서 할 일>
완료 조건: <작업 완료 기준>
```

> Handoff 문서의 **필수 섹션·작성 규칙**(상태 서술형 vs 명령형, 라인 번호 포함, 검증 지시 필수), **Handoff = hypothesis** 원칙, **Report Registry 패턴** 등 4계층(Tier) 상세는 `concepts/session-handoff.md` 참조.

---

## 5. Plan mode 먼저 거친 후 구현

실행 모드로 바로 들어가면 탐색, 설계, 구현이 같은 비용 센터에서 처리된다.

**절차:**
1. 관련 파일과 영향 범위 파악
2. 수정 후보와 접근 방식을 짧게 계획
3. 불필요한 범위 제거
4. 그 후 구현

**저자 보고 절감 20~30%**

## 6. `CLAUDE.md` 계층 구조로 반복 설명 외부화

```
<project-root>/
├── CLAUDE.md              # 프로젝트 전체
├── <source-dir>/
│   └── CLAUDE.md          # 소스 코드 컨벤션
├── <infra-dir>/
│   └── CLAUDE.md          # 인프라/환경 상세
└── <tests-dir>/
    └── CLAUDE.md          # 테스트 전략/실행 방법
```

**`CLAUDE.md` 필수 항목:**
- 핵심 기술 스택과 아키텍처
- 코딩 컨벤션
- 현재 스프린트 목표와 블로커
- compact 시 보존할 정보
- "Load on Demand" 링크

**역할**: 모든 것을 담는 문서가 아니라 **무엇을 바로/나중에 읽을지 결정하는 인덱스**.

## 7. Skills로 "항상 로드"를 "필요시 로드"로 변경

**3단계 Progressive Disclosure:**

| 단계 | 로드 시점 | 내용 |
|------|-----------|------|
| YAML frontmatter | 항상 | 스킬 이름, 설명, 트리거 |
| `SKILL.md` 본문 | 관련성 판단 시 | 실행 절차, 규칙 |
| `references/` | 필요시만 | 상세 체크리스트, 정책 문서 |

**저자 보고 성과:** 입력 토큰 26% 감소, 평균 성공률 +16.2%p 향상 — 측정 주체·대상 작업이 원문에 없어 재현 조건을 알 수 없다.

---

## 8. 고노이즈 작업은 서브에이전트로 격리

웹 검색·긴 로그 분석·광범위 코드 탐색처럼 **읽는 양은 많은데 남길 것은 적은** 작업은 메인 컨텍스트에서 떼어내 서브에이전트에 맡기고, 결과 요약만 돌려받는다.

> 격리 대상 목록과 **과다 생성이 오히려 역효과인 이유**(조율 오버헤드가 작업량을 넘어선다)는 `concepts/session-handoff.md` §Tier 1 참조. 여기에는 원칙만 둔다 — 같은 목록을 두 곳에 두면 한쪽만 고쳐져 갈라진다.

---

## 9. 검색 기반 컨텍스트 주입을 기본값으로

**안 되는 방식:**
```
"전체 소스 디렉토리를 보고 알아서 수정해줘"
```

**올바른 방식:**
```
"<module>/<file>.py의 <function> 함수에서 타임아웃 에러가
발생한다. 관련 코드를 확인하고 수정해줘"
```

1. 먼저 검색으로 관련 파일/심볼을 찾고
2. 관련 코드 조각만 컨텍스트에 넣고
3. 그 범위 안에서 작업

**저자 보고 절감 80% 이상**

---

## 10. MCP 서버 활성화 자체가 비용

활성화된 서버와 도구가 많을수록 컨텍스트와 시스템 지시문이 증가한다. 현재 작업에 필요한 MCP 서버만 활성화하고, 불필요한 서버는 비활성화한다.

**본질**: "많이 연결"이 아니라 **"필요할 때만 연결"**.

> 다만 끄는 것만이 수단은 아니다. 도구 스키마를 **선언만 해두고 실제로 쓸 때 불러오는** 지연 로딩·도구 검색 방식이 생겨서, 서버를 연결해 둔 채로도 상시 점유를 줄일 수 있다. 원칙은 §7 Skills 와 같고("항상 로드"를 "필요시 로드"로) 적용되는 층만 다르다.

---

## 안티패턴 (피해야 할 것)

- "전체 프로젝트를 보고 알아서 해줘" 같은 넓은 요청
- 한 세션에 탐색 + 구현 + 디버깅 + 회고 모두 누적
- 대형 tasks.md, 거대한 규칙 파일을 항상 통째로 로드
- 빌드 로그, diff, 검색 결과를 압축 없이 그대로 붙여넣기
- 현재 작업과 무관한 MCP 서버/도구 상시 활성화
- 큰 컨텍스트 창이 있으니 정리 불필요하다는 태도

> "긴 컨텍스트는 쓰레기를 더 많이 담을 수 있게 해줄 뿐, 중요한 정보를 더 잘 고르게 해주지는 않는다."

---

## 핵심 원칙

> "모델에게 많은 것을 보여주지 말고, 지금 필요한 것만 정확히 보여줘라."

1. **세션을 짧게 유지**한다
2. **반복되는 설명은 문서/skill로 외부화**한다
3. **큰 태스크는 인덱스와 계획 단계로 쪼갠다**

> "좋은 바이브 코더는 긴 프롬프트를 쓰는 사람이 아니라, 컨텍스트를 설계하는 사람이다."

토큰을 아끼는 팀이 생산성이 높은 이유는 돈을 적게 써서가 아니라, **모델이 헷갈릴 여지를 줄였기 때문**이다.
