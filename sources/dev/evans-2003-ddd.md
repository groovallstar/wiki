# Evans (2003) — Domain-Driven Design: Tackling Complexity in the Heart of Software

- **저자**: Eric Evans
- **연도**: 2003
- **매체**: Addison-Wesley (단행본)
- **링크**: https://www.domainlanguage.com/ddd/
- **유형**: 1차 문헌 (DDD 원서)

## 핵심 요지

도메인 전문가와 개발자가 같은 어휘로 말하지 않으면 매 대화·문서·코드 사이에
번역 단계가 발생하고, 그 번역 어딘가에서 의미가 깎이면 잘못된 모델이 코드에
굳는다. 해법은 양쪽이 공유하는 단일 어휘집(**Ubiquitous Language**) 을 두고,
회의·이슈·코드·테스트·로그 모두 같은 단어로 일관 표기하는 것이다. 어휘는
모델과 동의어이며, 어휘가 흔들리면 모델·코드·테스트 전체가 동시에 흔들린다.

## 주요 내용

- **Ubiquitous Language**: 모든 의사소통에서 같은 어휘를 강제. 별도의 "사용자
  언어"와 "개발자 언어"를 두지 않는다.
- **모델 = 어휘**: 어휘집의 변화는 곧 도메인 모델의 변화이며, 코드 리팩터링
  대상이 된다.
- **단일 어휘집의 한계**: 한 어휘가 두 맥락에서 서로 다른 의미를 가지면 단일
  어휘집은 깨진다 — 어휘집을 분할해야 한다.
