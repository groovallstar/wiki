# 정도현 — 바이브 코딩의 토큰 관리 전략

- **저자**: 정도현 (로보코 수석 컨설턴트)
- **매체**: roboco.io 블로그
- **링크**: https://roboco.io/posts/vibe-coding-token-management-strategy/
- **유형**: 2차 자료 (실무 가이드/블로그)

## 핵심 명제

**"토큰 부족은 모델 성능의 문제가 아니라 컨텍스트 운영 방식의 문제이다."**
실제 원인은 토큰 소진이 아니라 **컨텍스트 오염(Context Rot)** — 누적된 대화 로그·실패 시도·폐기 정보가 모델을 혼란시키는 현상. 해법은 더 큰 모델이 아닌 "더 깨끗한 컨텍스트".

## 11가지 전략 (요약)

1. `.claudeignore`로 불필요 파일 차단 (30~40% 절감)
2. tasks.md 분할로 인덱스 구조 도입 (실측 76% 절감 사례)
3. `/clear`·`/compact` 전략적 활용 (70% 도달 시)
4. HANDOFF.md로 세션 인계 비용 최소화
5. Plan mode 우선 (20~30% 절감)
6. CLAUDE.md 계층 구조로 반복 설명 외부화
7. Skills로 "항상 로드 → 필요시 로드" 전환 (입력 토큰 26%↓, 성공률 +16.2%p)
8. 고노이즈 작업은 서브에이전트로 격리
9. 검색 기반 컨텍스트 주입을 기본값으로 (80%+ 절감 가능)
10. MCP 서버는 필요할 때만 활성화
11. 도구별 역할 분리 (Claude Code / Gemini / Codex)

> 검증 메모 — 위 목록은 원문이 적은 그대로다. 두 항목은 이후 사실이 달라졌다.
>
> - **1번의 수단**: 원문은 `.claudeignore` 로 차단해 30~40% 를 아낀다고 적었으나 그 파일은 구현돼 있지 않다. 원칙은 유효하고 수단만 대체된다 — 상세는 `concepts/token-management.md` §1.
> - **11번의 전제**: 원문은 Claude 쪽 컨텍스트가 작다고 보고 긴 컨텍스트 작업을 다른 도구로 넘기라고 처방했는데, 그 제약이 사라졌다(현행 주요 모델은 1M 컨텍스트). 제약이 없어지면 처방도 근거를 잃으므로 개념 페이지에서는 이 항목을 뺐다.
>
> 절감률은 워크로드·측정 방법이 원문에 없어 **저자 보고 단일 사례**로만 읽는다.

## 핵심 원칙

- "모델에게 많은 것을 보여주지 말고, 지금 필요한 것만 정확히 보여줘라."
- 좋은 바이브 코더는 긴 프롬프트를 쓰는 사람이 아니라 **컨텍스트를 설계하는 사람**.
- 토큰 절약 ≠ 비용 절감, 진짜 효과는 **모델의 혼란 요소 제거**.
