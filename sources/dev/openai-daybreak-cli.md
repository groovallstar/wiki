## 핵심 요지

대화형 CLI에서는 `/daybreak`로 이후 요청의 Daybreak 설정을 전환한다. 명령 표시,
저장된 설정과 실제 계정·모델 지원 여부를 각각 확인해야 한다.

## 주요 내용

- 문서는 관련 동작에 CLI 0.163.0 이상이 필요하다고 설명한다.
- `/daybreak`는 활성 대화에 적용되고 새 세션의 기본값으로 저장된다. 재개·분기한
  세션은 저장된 선택을 유지하며 새 기본값이 그 선택을 대체하지 않는다.
- 자동 실행에는 최상위 `daybreak=true` 설정을 전달할 수 있다. 실행별 설정은
  저장된 기본값보다 우선하며, 실제 실행 환경의 설정을 확인해야 한다.
- 계정의 Daybreak 접근과 선택한 모델의 지원 여부를 확인한다. 활성화 후에도
  요청이 거절될 수 있으며, 거절된 요청은 자동으로 재시도되지 않는다.
- 모델 선택기의 제공 목록은 별도로 갱신될 수 있다. 문서 갱신이나 모델 항목의
  노출 자체를 모델 가중치 패치의 증거로 보지 않는다.

### 버전·기능 설정 및 검증 범위

- 로컬 관측: CLI 0.165.0에서 해당 기능이 꺼진 조건으로 확인했다.
  `codex --no-daemon --enable cli_daybreak`로 시작하자 `/daybreak`가 표시됐으며
  켜짐·꺼짐 전환 메시지를 확인했다.
- 같은 확인일의 로컬 모델 목록에는 Daybreak Blue 항목의 ID가
  `gpt-daybreak-blue-latest`로 표시됐다. 이 목록만으로 서버의 실제 기반 스냅샷을
  식별할 수는 없다.
- 관측은 명령 표시와 토글 전환에 한정한다. 모델 요청, 거절 완화의 실제 적용과
  성능은 검증하지 않았다. `--no-daemon`을 일반적인 필수 옵션으로 제시하지 않는다.

이 절의 로컬 관측은 공식 문서의 주장과 구분한다. 특정 계정의 관측을 모든
설치와 계정에 일반화하지 않는다.
당시 공식 원문 전체의 별도 스냅샷은 보관하지 않아 이후 원문의 변경 내역을
이 노트와 링크만으로 완전히 복원하지 못할 수 있다.
