## 핵심 요지

Daybreak Blue를 이용한 보안 연구에서 유용한 취약점 발견 경험과 작업성 저하를
함께 보고한다. 작성자는 관측한 지침 차이와 서버 모델 자체의 변화 여부를 구분한다.

## 주요 내용

- 초기 사용에서는 실제 취약점 발견에 도움이 됐다고 주장하지만 대상과 공개 전
  취약점은 가려져 있어 이 글만으로 발견 성과를 독립적으로 검증할 수는 없다.
- 이후 반복적인 범위 확인, 추가 질문과 중단이 작업 속도와 보고서 품질을
  떨어뜨렸다는 경험을 서술한다. 이는 통제된 성능 벤치마크가 아니다.
- 같은 모델 ID와 가시적인 설정을 사용하고 약 62초 차이로 시작한 두 세션에서
  기본 지침의 길이와 내용이 달랐다고 보고한다. 이 사실만으로 원인을 확정하지 않는다.
- 처음에는 Daybreak와 일반 Sol의 비교로 생각했던 실행을 정정한다. 자식 세션에
  다른 모델을 지정해도 부모의 기본 지침이 상속돼 깨끗한 모델 비교가 아니었다.
- 작업성 평가에는 모델 외에도 세션 초기화와 지침 상속을 통제해야 한다는 사례로
  활용하며, 현재 모델의 성능 순위나 보안 정책 우위로 일반화하지 않는다.
